# OwnTake 产品设计

> 状态：v0.1 设计基线，正式产品实现待开始。本文描述目标行为；静态原型中的交互仅用于检验流程，不代表模型、任务系统或导出能力已经实现。
>
> 关联：[文档入口](README.md) · [技术架构](architecture.md) · [实施计划](implementation-plan.md) · [可点击原型](prototype/README.md)

## 1. 产品定义

**OwnTake 是运行在自己电脑上的 AI 短片工作台：把一个想法拆成可编辑的分镜，用合适的模型或已有素材完成每个镜头，再组合成可以导出的作品。**

唯一目标用户是项目拥有者本人。首版围绕单人、单机、一个正在制作的项目设计，不引入账号、团队、订阅、支付或云端项目服务。建议以 4–8 个镜头、20–45 秒的短片作为第一次创作模板；这是降低初次使用复杂度的默认值，不是架构限制。

“本地运行”指界面、本地服务、数据库、项目素材和渲染在自己的电脑上运行。选择外部模型时，所需提示词和参考素材仍会发送到相应服务；只有接入具备所需能力的本地推理服务，相关推理才能离线运行。界面需要显示每次任务实际使用的连接和输入，避免把这两种情况混淆。

### 1.1 核心体验

- **以镜头为工作单位。** 修改一个镜头时，能看到它的意图、参考、候选结果、审核依据以及在成片中的位置。
- **人工编辑始终可用。** 可以不调用任何模型，手工写分镜、导入素材并完成导出；模型用于加快创作。
- **模型可以更换，创作状态可以保留。** 项目记录镜头意图和版本；模型调用记录具体执行计划，两者分开保存。
- **每次生成都有去向。** 知道任务是否提交、是否仍在运行、结果是否下载、当前选用了哪个版本。
- **局部修改只影响实际依赖它的内容。** 改字幕不应重新生成视频；替换背景应明确标记相关镜头需要重新检查。

### 1.2 首版支持的创作素材

| 素材方式 | 适合内容 | 产品处理方式 |
| --- | --- | --- |
| 导入图片、录屏、实拍视频 | 真实产品界面、个人素材、已有片段 | 读取媒体信息，选择裁切方式与使用区间，保留来源 |
| 图片生成或编辑 | 风格样张、角色/场景参考、静态镜头 | 创建候选版本，由用户选择用于分镜或视频生成 |
| 视频生成 | 创意场景、镜头运动、过渡素材 | 根据能力清单编译生成计划，异步执行并下载结果 |
| 本地排版与合成 | 字幕、片名、Logo、片尾文字 | 使用确定性的排版与媒体处理，不要求生成模型绘制准确文字 |
| 导入音频 | 背景音乐、配音、环境声 | MVP 支持简单使用与混音，精细编辑和 TTS 放到后续阶段 |

真实界面应优先使用截图或录屏。首尾帧是可选的生成方式：只有镜头意图需要、且具体模型端点支持时才使用，不要求所有镜头都构造首尾帧。

## 2. 产品范围与版本边界

### 2.1 自用 MVP 的完成标准

P1–P3 完成后，用户应能独立完成以下流程：

1. 创建本地项目，填写或手动调整短片目标、画幅、风格和分镜。
2. 导入已有素材，或通过至少一个经过验证的图片模型与一个视频模型生成素材；两者可以来自同一服务，也可以分别接入。
3. 检查能力不匹配、估算费用和使用输入，再执行任务。
4. 离开页面、刷新页面或重启本地服务后，仍能找到项目、任务状态和已经下载的结果。
5. 对照分镜意图查看候选，选择一个明确的素材版本；可以只重新制作其中一个镜头。
6. 调整顺序、基本裁切、时长、基础字幕和一条导入音轨，预览后导出 MP4。

### 2.2 首版不做

- 多用户、多设备实时协作、云端素材管理和项目同步。
- 自建模型训练平台、模型托管集群、必须依赖本地大模型的安装流程。
- 完整专业剪辑软件的轨道、特效和插件体系。
- 任意提示词都能“一次生成合格影片”的承诺。
- 一次接入所有厂商；先验证少量真实连接，再按相同合同扩展。
- 强制使用 Claude Code、Codex 或特定视频模型。
- 桌面安装包、托盘、自动升级作为 MVP 的前置条件。

## 3. 信息架构：六个主要页面

| 页面 | 用户要完成的事 | 主要内容 | 关键操作 |
| --- | --- | --- | --- |
| 项目 | 开始或恢复一部短片 | 最近项目、作品状态、新项目简报 | 新建、打开、复制简报模板、打开项目目录 |
| 分镜工作台 | 完成一个镜头并理解全片结构 | 左侧镜头列表，中间画面/候选/审核，右侧意图与生成参数，底部时间线 | 编辑镜头、选择参考、生成计划、选择候选、局部修改 |
| 素材 | 找到并复用已有内容 | 图片/视频/音频、来源、版本、使用关系 | 导入、预览、分配到镜头、定位被引用位置 |
| 任务 | 理解正在发生什么并恢复异常 | 提交、运行、下载、渲染任务与最近事件 | 取消、恢复查询、核对未知提交、重试可安全重试的步骤 |
| 导出 | 确认本次成片使用的内容 | 时间线、缺失项、字幕/音轨、输出设置、历史导出 | 修复阻塞、预览、本地渲染、打开输出文件 |
| 设置 | 连接能力和本地工具 | 模型连接、能力验证、运行时、FFmpeg、默认参数、预算策略 | 健康检查、验证连接、修改默认值、诊断可执行路径 |

新建项目是项目页中的流程，不另设一级导航。聊天助理可以作为分镜页侧栏，默认绑定当前项目与所选镜头；不把导演、审核、监督等逻辑角色拆成多组聊天窗口。

### 3.1 分镜工作台布局

- **左侧：镜头序列。** 显示序号、简短意图、时长、所选素材、待处理状态。选中镜头时同步定位底部时间线。
- **中间：可比较的结果。** 主预览、候选缩略图、参考素材、版本信息。审核和修改影响作为同一区域的标签页。
- **右侧：执行前可理解的设置。** 显示生成方式、连接/模型、输入引用、尺寸/时长、估算费用、能力验证结果。
- **底部：全片上下文。** MVP 提供顺序、时长、裁切与基础字幕；复杂多轨编辑进入 P4。

桌面窗口应优先保障预览与镜头列表可读。窄窗口将右侧配置折叠为抽屉；不把所有操作压缩成无法辨认的图标。耗时操作必须在按钮附近给出状态，并能在任务页继续查看。

## 4. 核心用户流程

### 4.1 从想法到分镜

用户填写主题、观众或使用场景、目标时长、画幅、内容约束与参考素材。可以手工新增镜头，也可以请求助理生成结构化草稿。

草稿同时包含每镜的叙事目的、画面、运动、文字/配音、时长和建议素材方式。应用前显示差异；用户可以修改或只接受部分镜头。模型输出必须经过结构校验，不能因为返回一段看似合理的自然语言就直接覆盖项目。

“导演”“审核”“监督”“执行代理”是有不同权限的任务角色。MVP 以手动操作和有界原生任务循环为基础；CC、Codex 等执行环境可以在 P4 接入。模型供应商、Agent 运行时与媒体工具是三个独立选择。

### 4.2 从分镜到候选素材

1. 选择镜头意图与参考素材。
2. 选择素材方式：导入、图片、视频或本地合成。
3. 查看系统编译出的生成计划：实际模型端点、输入方式、尺寸/时长、引用素材、费用边界。
4. 修复能力冲突，或明确接受另一种方案。不能悄悄丢弃尾帧、音频或参考图。
5. 提交后得到持久任务；界面可以离开，任务继续由本地服务管理。
6. 远端成功后先下载、校验并登记本地素材，再进入可审核状态。
7. 查看候选并选择用于镜头的版本。候选到达并不意味着自动替换已选素材。

生成按钮根据当前计划显示“生成候选”或具体阻塞原因。项目策略已经授权的模型、费用和重试范围内，不重复要求批准；超出范围时，在同一计划摘要上进行一次具体确认。

### 4.3 局部修改

用户先看到影响范围，再应用修改。系统更新相关修订号和审核有效性，不自动启动新的付费生成。

| 修改 | 默认影响 | 应保留的内容 |
| --- | --- | --- |
| 改字幕文字、字号或位置 | 字幕图层与最终渲染 | 已生成视频、其画面审核与候选 |
| 改背景音乐音量 | 混音与最终渲染 | 画面素材、镜头选择 |
| 调整镜头顺序 | 时间线、连接处检查与最终渲染 | 各镜头素材版本 |
| 改人物服装、背景或关键动作 | 相关镜头的视觉计划与审核有效性 | 原候选和原已选素材，供比较或回退 |
| 改项目默认模型 | 以后创建的计划 | 已冻结的计划、在途任务与现有素材 |
| 为当前镜头换模型 | 新的执行计划，必要时重新确认输入 | 原计划、任务与候选，不做原地改写 |

影响以实际依赖关系为准。例如画面中本来就包含需要变化的文字时，修改该视觉要求可能影响画面；独立字幕图层仍只影响合成。

### 4.4 从候选到导出

用户选定每个镜头的素材版本，确认顺序、使用区间、字幕、音轨和输出设置。系统生成一个冻结的时间线版本，随后渲染该版本。渲染期间继续编辑会形成新的版本，不改变在途导出的内容。

导出前分为两类检查：

- **必须修复的技术问题：** 文件缺失或损坏、未选素材、引用无法解析、时间区间非法、渲染工具不可用。
- **需要用户判断的创作问题：** 画面含义、动作、节奏、声音、风格或过期审核。清楚显示已检查的范围；用户可以检查后接受并记录备注。

导出完成后显示输出文件、对应时间线版本、参数、耗时和警告。原项目和素材不随导出自动清理。

## 5. 功能需求与验收

下表是需求编号的权威入口；阶段文件使用相同编号。P0 不实现这些正式产品功能。

| 编号 | 需求 | 最早交付 | 最低验收情景 |
| --- | --- | --- | --- |
| FR-01 | 创建、打开与恢复本地项目 | P1 | 重启服务后项目、简报和素材引用仍可读取 |
| FR-02 | 本地工具与连接设置 | P1 起 | FFmpeg 缺失时显示可执行路径诊断；P2/P3 分别显示推理和生成连接的能力验证状态 |
| FR-03 | 导入、探测、预览与引用素材 | P1 | 同名文件导入不会覆盖原素材；缺失媒体可定位和重新关联 |
| FR-04 | 最小顺序时间线与本地导出 | P1 | 导入 3 个片段后按所选顺序导出可播放 MP4，保持约定画幅与时长 |
| FR-05 | 持久任务与事件进度 | P1 起 | 刷新页面可恢复渲染进度；P3 可恢复远端轮询和下载 |
| FR-06 | 简报、风格说明与结构化分镜 | P2 | 手工编辑分镜和接受部分模型草稿均能保存；无模型也可继续 |
| FR-07 | 与当前镜头绑定的有界助理 | P2 | 超时或无效结构不会覆盖现有分镜；用户可查看应用差异 |
| FR-08 | 镜头修订、候选与显式选择 | P2 起 | 新候选不覆盖所选素材；切回历史候选后可导出对应版本 |
| FR-09 | 能力清单、验证与生成计划 | P2 合同/推理，P3 图片视频 | 仅支持首帧的模型不能执行首尾帧计划，界面明确提出重规划 |
| FR-10 | 图片/视频生成适配器 | P3 | 至少一个图片连接和一个视频连接完成真实请求到本地素材的闭环 |
| FR-11 | 提交歧义、取消与恢复 | P2 基础，P3 异步生成 | 请求可能已受理时保留未知状态，重启不再次自动付费提交；P3 增加远端任务关联/取消 |
| FR-12 | 预算、费用预留与重试策略 | P2 最小保护，P3 完整台账 | 外部推理已有调用审计、次数/费用边界；P3 增加生成预留/对账；未知费用不当作零 |
| FR-13 | 下载入库与产物完整性 | P3 | 下载中断不会把半文件标为可用；旧任务结果不会完成新修订 |
| FR-14 | 审核依据与人工确认 | P3 基础，P4 增强 | 可见技术检查结果和未检查项目；静帧审核不被标成完整视频审核 |
| FR-15 | 局部修改与依赖失效 | P3 | 修改字幕不提交新视频任务；改视觉要求仅标记受影响内容 |
| FR-16 | 基础字幕、导入音轨与生成素材导出 | P3 | 混用导入、生成和合成素材完成短片；字幕文字以确定性排版输出 |
| FR-17 | 本地访问与凭据隔离 | P1 起 | 默认仅监听回环地址；前端、项目快照和普通日志中没有模型密钥 |
| FR-18 | 项目备份与可诊断性 | P1 起，P3 完整 | 能用一致性备份恢复素材与引用；诊断包隐去密钥和不必要的原始内容 |
| FR-19 | 精剪、音频与审核扩展 | P4 | 新增能力保持旧项目兼容，审核报告说明素材版本和覆盖范围 |
| FR-20 | 可替换 Agent 运行时 | P4 可选 | 运行时通过宿主的调用遵守预算、文件范围和计划应用边界；额外本机权限如实标明 |
| FR-21 | 桌面启动与服务生命周期 | P5 可选 | 桌面壳与浏览器入口共享项目格式，窗口关闭不默默终止任务 |

### 5.1 交互文案与状态规则

| 产品展示 | 内部语义 | 可用操作 |
| --- | --- | --- |
| 计划已准备 / 待确认 | 输入和执行计划已冻结，尚未发起付费请求 | 查看、确认、放弃；修改则新建计划 |
| 正在提交 | 正在与供应商建立任务关系 | 查看；重复点击不会重复提交 |
| 提交结果待核对 | `submission_unknown`，远端是否受理尚不确定 | 查询已知请求、输入/核对远端任务；不能提供无条件“再试一次” |
| 生成中 | 已有远端任务标识 | 查询、请求取消；不能承诺取消成功或费用返还 |
| 正在保存结果 | 远端成功，本地仍在下载或校验 | 重试下载；不重新生成 |
| 待查看候选 | 本地素材已完整登记 | 预览、审核、选择；不是自动通过 |
| 失败 | 已知某一步未完成 | 显示失败步骤以及该步骤可安全执行的恢复方式 |
| 已请求取消 | 本地已发起取消，结果尚未确认 | 继续查询；保留结果和费用记录的可能性 |
| 已取消 | 已按对应执行语义确认停止 | 查看历史；费用状态独立显示 |

技术架构规定具体状态机；产品不能把“停止轮询”“任务取消”“不再收费”合并成同一种状态。

### 5.2 审核的诚实边界

审核结果使用 `pass`、`needs_fix`、`needs_human`、`not_checked`，另记录报告是否因输入或版本变化而过期。报告绑定素材版本、计划和检查规则。

基础检查读取文件、编码、时长、尺寸、引用、字幕与音轨等可确定信息。语义审核可检查抽帧或视频，但必须说明实际采样时间点、是否包含音轨、使用的模型及证据。动作连贯性、主观节奏和作品表达最终由用户判断。缺少证据时显示“未检查”或“需人工判断”，不生成看似精确的虚构分数。

## 6. 成本与执行权限

设置分为项目默认策略与单次计划。项目策略包括允许的连接、单次/累计费用上限、并发上限、自动恢复范围和是否允许自动选择候选。MVP 默认由用户选择候选；以后可在明确范围内加入自动选择策略。

这些保护从首次外部计费调用开始生效。P2 接入推理连接时就需要调用审计、请求次数/费用边界和响应不明时不自动重发；P3 扩展为图片/视频异步任务的完整预留与对账，不把推理请求视为天然免费。

费用展示区分估算、预留、已确认实际费用和未知费用。不同币种不能直接相加；没有可靠价格或上界时，由用户为该计划填写可接受的预留额并确认，或先配置价格依据。已授权边界内的普通执行不重复弹窗。

本地预留决定应用是否继续发起请求，不等同于供应商账单的硬上限。允许价格未知的调用时，界面明确说明预留与实际费用可能不同，不能承诺一个无法由端点强制执行的价格上限。

轮询、下载和本地渲染的恢复与重新生成分开。明确失败后再次生成也可能产生新费用，必须建立新的生成意图并重新检查额度。提交结果未知时保留预留，不能通过超时、取消或重启自动释放为“未消费”。细节见[技术架构](architecture.md)。

## 7. 异常与恢复体验

| 情景 | 用户看到什么 | 产品应采取的行为 |
| --- | --- | --- |
| 浏览器刷新/关闭 | 重新打开后恢复当前项目和任务 | 服务继续工作，前端重新查询并接续事件 |
| 本地服务退出/机器睡眠 | 显示恢复中和最后确认状态 | 恢复本地任务或查询已知远端任务；不盲目重发未知提交。只有明确幂等保证时，才按原键、原请求及有效窗口安全核对或重传 |
| 供应商完成但下载失败 | “结果已生成，保存失败” | 使用已有任务结果重试下载，必要时提示结果链接过期 |
| 受管项目媒体被移动/删除 | 具体镜头与素材显示缺失 | 允许重新关联，不能静默替换为另一个同名文件；已复制导入的素材不因外部源文件移动而失效 |
| 接入模型不支持当前输入 | 参数区显示冲突与可选修订 | 阻止提交，用户接受修订后创建新计划 |
| 任务运行时修改了镜头 | 旧结果标记所属修订 | 作为历史候选保存，不自动完成新要求 |
| 磁盘不足 | 明确保存/渲染所需空间和失败步骤 | 保留可恢复状态，不把临时文件登记为成品 |
| 模型返回错误的分镜结构 | 助理显示结构校验错误 | 保持已有项目，不应用部分损坏状态 |

## 8. 验收作品与质量标准

建议维护一套不含真实密钥、可公开分享的 4 镜头演示项目：导入镜头、生成镜头、本地文字合成镜头各至少一个，包含基础字幕与一条导入音轨。静态原型可以展示这套场景，但正式验收必须使用实现后的真实文件与可用模型连接。

| 验收维度 | 判断标准 | 对应阶段 |
| --- | --- | --- |
| 无模型可用 | 手工分镜 + 导入素材仍能完成本地导出 | P1–P2 |
| 能力适配可解释 | 不支持的首尾帧/参考输入被明确拦截 | P3 |
| 项目可恢复 | 关闭页面、重启服务后不丢所选版本和任务关系 | P1、P3 |
| 付费调用不被盲目重发 | 响应丢失的提交保留为未知，能人工核对 | P2 起，P3 扩展 |
| 局部修改生效 | 字幕编辑只产生新的合成版本，不重新生成画面 | P3 |
| 结果可追溯 | 成片可追到时间线、所选素材、生成计划和模型连接 | P3 |
| 工具可理解 | 缺少 FFmpeg、CLI 路径或模型凭据时能定位问题 | P1、P4 |
| 创作体验完整 | 用户能独立完成并找到一条导出的短片 | P3 MVP |

不以商业指标衡量本项目。早期观察完成一条短片需要多少次手工跳转、异常是否可自行恢复、局部修改是否节省重复生成，以及最终文件是否符合创作意图。

## 9. 已定决策与保留选项

**已定：** 本地 Web 优先、单人单机、模型能力适配、镜头与版本为核心、SQLite 与本地文件、FFmpeg 渲染、持久任务、保留人工编辑入口。

**实施时再选择：** 首个真实图片/视频连接、具体模型、认证方式、预算默认值、字幕字体、精剪程度与是否需要桌面壳。选择应根据用户现有账号、机器和日常作品验证，不阻碍 P1/P2 先完成。

**待使用反馈决定：** 自动选候选、全片语义审核、TTS、风格/角色资产包、CC/Codex 运行时以及 Electron。每项扩展都应先证明能减少实际操作，再加入主流程。
