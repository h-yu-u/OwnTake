# P0 · 设计基线与交互原型

> 状态：本次文档交付范围；正式应用尚未实现。原型验收以[原型说明](../prototype/README.md)中的实际记录为准。

## 目标

把“自己电脑上的 AI 短片工作台”收敛成可实施的产品边界、界面流程和技术合同。让后续开发可以围绕明确的验收场景推进，而不是先搭一组模型调用按钮。

## 前置条件

- 已确定项目名称 OwnTake 与仓库 `h-yu-u/OwnTake`。
- 用户明确以本机自用为目标，不需要商业化或团队服务。
- 选择本地 Web + Node.js + SQLite + 本地文件 + FFmpeg 作为首版方向。

原型的模型、任务、素材和导出是演示数据。原型不应访问真实模型、保存密钥、收费或声称产生了实际视频文件。

## 设计与检查顺序

1. 明确人工可完成的创作流程，并将图片/视频生成作为可替换能力嵌入。
2. 固定六个主要页面和分镜工作台布局，避免逻辑角色变成多个独立应用。
3. 定义镜头意图、执行计划、调用尝试、素材版本、审核与时间线之间的关系。
4. 用原型演示能力冲突、候选选择、局部修改和未知提交的恢复入口。
5. 把可靠性要求映射到首次引入对应能力的阶段。
6. 检查文档链接、代码语法、原型主要操作和状态文案，记录实际完成的验证。

## 验收情景

| 情景 | 通过条件 |
| --- | --- |
| 进入工作台 | 能看出当前项目、所选镜头、候选和生成设置的位置 |
| 选择能力不匹配的演示模型 | 首尾帧需求被明确拦截，不能静默忽略尾帧 |
| 查看模拟结果 | 明确区分任务完成、候选可用与用户选择 |
| 修改独立字幕 | 可见影响是合成/导出，画面候选得以保留 |
| 查看未知提交 | 提供核对思路，不鼓励直接重复付费请求 |
| 阅读实施计划 | 能辨认 P3 是自用 MVP，P5 桌面端是可选项 |

## 本阶段不做

正式 Vue/Node 应用、真实 SQLite 数据、远端模型请求、媒体渲染、桌面打包、付费测试或产品上线。静态原型中的本地保存不等价于正式项目存储与备份。

## 退出门槛

文档与原型使用同一套核心术语，关键状态和异常都有可理解的入口；明确哪些是设计、哪些是模拟、哪些尚未验证。将实际 QA 结果记录后，可以开始 P1。未来调整视觉细节无需阻塞本地底座开发。
