# P1 · 本地底座与导入导出切片

> 状态：待实现。覆盖 FR-01–FR-05、FR-17，以及 FR-18 的基础部分。

## 目标

不依赖任何 AI 模型，完成“启动 → 新建项目 → 导入素材 → 排列片段 → 导出 MP4 → 重开项目”的真实闭环。用这个切片验证文件、媒体、存储和任务生命周期，后续生成结果复用同一套能力。

## 前置条件

- P0 的项目格式、任务和文件归属原则已明确。
- 确认本机 Node.js 运行环境、FFmpeg/ffprobe 可执行文件和基础编解码能力。
- 使用小型、可公开分享、来源明确的媒体样例，不把私人素材或凭据提交到仓库。

## 范围与建议模块

| 模块 | 交付行为 |
| --- | --- |
| `apps/web` | 项目、素材、简易时间线、导出和工具设置的真实操作界面 |
| `apps/server` | 回环地址 HTTP API、静态资源、SSE/状态查询、单实例生命周期 |
| `packages/storage` | SQLite 迁移、项目/素材/任务记录、事务与一致性备份 |
| `packages/media` | 媒体探测、缩略图、裁切/适配画幅、顺序拼接、输出探测 |
| `packages/domain` | 最小项目、素材版本、时间线快照与本地任务状态 |
| `packages/contracts` | 输入 schema、错误码和不含密钥的响应结构 |

目录仅是建议代码边界，不是独立服务。一个本地 Node 服务管理所有任务；媒体处理通过受控子进程执行。

## 实施顺序

1. **启动与边界。** 确定配置和应用数据目录；默认监听 `127.0.0.1`，设置本地会话/来源校验；启动时检查 Node、FFmpeg、ffprobe、输出目录权限。
2. **存储骨架。** 创建 SQLite 迁移和项目目录规范；对外使用资源 ID，文件引用与实际路径分开；禁止任意路径读写与任意 shell 命令。
3. **导入切片。** 复制媒体到受管目录，经探测后登记来源、哈希、尺寸、时长和媒体类型；文件重名不能覆盖。预览读取受控媒体地址。
4. **最小时间线。** 选择片段/图片顺序、使用区间、展示时长和统一画幅。先支持硬切；裁切/留边方式明确可见。
5. **本地任务。** 渲染任务与冻结时间线在开始执行前落库；提供进度查询、SSE 与停止请求。服务恢复时识别未完成的本地工作，按安全步骤重新执行。
6. **导出。** 使用参数数组启动 FFmpeg，写入临时路径，完成后探测并原子发布输出。建议首个预设为常用 MP4/H.264/AAC，但必须以本机实际工具能力检查为准。
7. **恢复与诊断。** 重新打开项目、重新关联缺失文件、检查磁盘空间、导出脱敏诊断；给出并验证一致性备份与恢复步骤，首版可使用明确的维护命令，P4 按需要完善打包界面。

在浏览器中点“关闭页面”不结束服务；服务退出或机器睡眠后的行为必须明确。初版可以在恢复时重做尚未成功发布的本地渲染，不能把残留临时文件当作已完成作品。

## 验收情景与失败测试

| 情景 | 通过条件 |
| --- | --- |
| 导入 3 个不同尺寸/时长的片段 | 有正确媒体信息和预览；同名源文件不覆盖 |
| 调整顺序与使用区间后导出 | 结果可播放，顺序、画幅与时长符合冻结的时间线 |
| 渲染中刷新页面 | 任务继续，重连后显示真实进度或最终结果 |
| 渲染中停止本地服务再启动 | 未完成工作被识别，临时文件不会出现在可用作品列表 |
| 删除或移动被引用的媒体 | 显示准确缺失项，允许重新关联，导出不静默跳过 |
| FFmpeg 不存在或执行失败 | 显示具体工具/步骤与可执行路径问题，不显示虚假完成 |
| 路径包含空格、中文或特殊字符 | 正确处理，无 shell 插值或路径逃逸 |
| 使用脱离允许项目目录的路径请求 | 服务拒绝访问；前端不能调用任意系统命令 |
| 恢复一份项目备份 | 数据库与媒体引用一致，可再次导出；备份不是简单复制正在写入的 SQLite 主文件 |

只保留验证上述风险所需的少量自动化和媒体样例。对输出进行 ffprobe 检查并至少人工播放一次，不能只检查文件是否存在。

## 本阶段不做

远端模型、LLM 剧本、复杂分镜审核、自动生成、预算台账、专业多轨编辑、Electron、云同步。可以暂时只提供当前已实现的页面，不把未实现按钮伪装成可用功能。

## 退出门槛

在目标电脑上完整演示一次从新建到导出，再关闭并重新打开；日常导出、项目打开与任务恢复不需要直接编辑数据库或运行内部脚本。文件访问、密钥隔离的基础设施和本地任务持久化已建立，备份维护步骤已验证，才能进入 P2。
