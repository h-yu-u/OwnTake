# P5 · 可选 Electron 桌面封装

> 状态：可选，不属于 MVP 前置条件。主要覆盖 FR-21。持续使用本地 Web 是完整有效的交付选择。

## 目标

当启动命令、文件选择和任务后台运行成为实际使用障碍时，为既有本地 Web + Node 核心加上桌面入口。保留浏览器版本与相同项目格式，不重写业务核心。

## 前置条件

- P3 核心稳定，项目、任务、渲染与恢复已有验证。
- 用户确认需要一键启动、原生文件选择、托盘或后台状态等具体收益。
- 决定桌面壳如何启动/监督本地服务，以及 Node、FFmpeg 和更新的分发方式。

P5 不要求先实现 P4 所有增强。反之，P4 的编辑或运行时功能也不依赖 Electron。

## 范围与建议模块

| 模块 | 交付行为 |
| --- | --- |
| `apps/desktop` | Electron 主进程、窗口、文件选择与有限 IPC |
| 本地服务启动器 | 启动、健康检查、单实例、退出协调、异常恢复 |
| 打包资源 | 前端构建、Node/媒体工具定位、版本与迁移策略 |
| 诊断界面 | 服务和工具状态、日志位置、异常提示 |

桌面渲染进程继续使用受限界面，不直接持有密钥、任意文件访问或 shell 权限。本地服务/宿主执行既有结构化合同。

## 实施顺序

1. 将本地核心的启动、停止和健康检查提取成可以复用的入口，验证浏览器使用方式仍然有效。
2. 建立最小 Electron 壳，加载现有前端，保持主进程、预加载桥与渲染进程边界。
3. 添加原生文件/项目目录选择与必要 IPC，所有操作仍通过受控资源与路径校验。
4. 明确窗口关闭、应用退出、后台继续和机器睡眠的不同语义。窗口关闭不能默默结束生成与渲染。
5. 处理多个应用实例、端口冲突、遗留服务、崩溃和重启；不要同时运行两个调度器争抢同一项目。
6. 在实际打包环境验证 FFmpeg、可选 CLI、凭据访问与文件权限，不假设终端 PATH 可直接继承。
7. 选择一种可操作的升级方式，迁移前提供一致性备份；自动更新可暂不实现。

## 验收情景与失败测试

| 情景 | 通过条件 |
| --- | --- |
| 双击启动 | 服务健康后打开工作台，缺失工具有可理解的诊断 |
| 已有浏览器服务时启动桌面壳 | 连接正确实例或明确处理冲突，不启动重复调度器 |
| 生成或渲染中关闭窗口 | 按明确配置继续后台任务，用户可以重新打开查看 |
| 用户明确退出应用 | 提示在途任务影响并有序停止；远端任务状态保留以供下次恢复 |
| 应用异常退出或机器睡眠 | 重新启动恢复已知任务，未知提交仍不自动重发 |
| 从浏览器转到桌面打开同一项目 | 项目、素材、所选版本和时间线完全兼容 |
| 可选 CLI 在终端可用但桌面 PATH 不同 | 使用显式配置定位，错误能定位到执行路径/认证 |
| 升级后数据库迁移失败 | 保留原数据与备份，不能以重置项目作为默认恢复 |

## 本阶段不做

重写成桌面专属业务层、远程同步、多用户支持、应用商店商业化或将 Electron 当作数据库/任务系统的替代品。Tauri 可以在将来有明确收益时单独评估，但不同时维护两种桌面壳。

## 退出门槛

在目标 Mac 上完成从安装/启动到短片导出，并验证关闭、退出、恢复和项目兼容。桌面入口减少启动负担，核心数据与执行可靠性不发生倒退。若这些收益尚不必要，可以停留在 P3/P4 的本地 Web 版本。
