# P4 · 编辑质量、审核与可选运行时

> 状态：可选后续增强，待实现。主要覆盖 FR-19、FR-20；基础恢复与付费安全已经在 P1–P3 完成。

## 目标

根据真实制作中的重复操作提升效率。优先解决最常见的编辑、声音和审核问题，再决定是否把 Claude Code、Codex 等运行时接进来，不为了“多 Agent”增加固定流程。

## 前置条件

- P3 MVP 已能稳定制作短片，并有实际使用记录。
- 当前最费时间或最影响成片的操作已经明确。
- 现有 schema、素材版本与任务恢复测试可以用于回归。

## 可独立选择的交付包

| 交付包 | 范围 | 建议模块 |
| --- | --- | --- |
| 编辑增强 | 更顺手的裁切、镜头连接、字幕样式、音量与淡入淡出；按需扩展轨道 | `apps/web`、`packages/media`、`packages/domain` |
| 音频增强 | 可选 TTS、配音管理、字幕对齐；输入音频和生成音频能力分别声明 | `packages/providers`、`packages/media` |
| 语义审核 | 抽帧/视频/音频检查、时间点证据、规则与人工决定 | `packages/runtimes`、`packages/providers` |
| Agent 运行时 | 可选 Claude Code/Codex 适配器，受限的宿主工具与结构化计划输出 | `packages/runtimes`、`apps/server` |
| 运行诊断 | 更清楚的工具路径、认证状态、上下文与进程错误 | `apps/server`、`apps/web` |

无需全部完成才获得收益。每次只选择一个存在明确使用价值的包，交付后用真实作品验证。

## 实施顺序

1. 记录上一阶段实际作品中最常见的返工点，选一个增强目标。
2. 先定义该功能需要的新输入、输出、依赖与审核覆盖，不绕开旧版本和预算语义。
3. 编辑增强继续编译到受控时间线与 FFmpeg 参数，不允许模型直接拼接任意终端命令。
4. 语义审核保持只读，输出检查对象、时间点、证据与不确定项；修复建议单独成为待应用计划。
5. 接入外部运行时时，显式配置可执行路径、`cwd`、环境、认证、超时和退出处理；不能依赖交互式 shell 自动加载的 PATH。
6. 运行时通过受限工具调用宿主能力；预算、文件范围、任务记录和计划应用仍由 OwnTake 控制。
7. 用旧项目、旧导出与已有异常场景做针对性回归，补充兼容迁移和使用说明。

CC/Codex 是 Agent 执行环境，不是与视频模型同类的模型名。把推理模型换成另一家供应商，不自动获得相同的文件工具、上下文管理或进程生命周期。运行时适配器必须说明实际可支持的任务。

宿主能够限制经自身接口的调用，但配置 `cwd` 和工具白名单不自动构成第三方 CLI 的操作系统沙盒。无法保证其全部权限时，应把它作为用户显式启用的可信本机扩展，标明自带工具与凭据边界，不宣称具有硬隔离能力。

## 验收情景与失败测试

| 情景 | 通过条件 |
| --- | --- |
| 开启新的字幕/音频能力 | 旧时间线与素材仍可打开；新增依赖只影响对应输出 |
| TTS 或审核调用失败 | 现有配音/审核不被覆盖，能够继续人工完成作品 |
| 只检查了少量帧 | 报告列出采样范围，不能自动宣称动作/声音均合格 |
| 审核提出修改建议 | 只形成计划，未经项目授权不自动生成新费用 |
| CC/Codex 不存在、未登录或退出异常 | 有具体诊断；用户仍可用原生/手工流程 |
| 运行时通过宿主请求越界文件或额外工具 | 宿主拒绝并记录；外部 CLI 自带工具的额外权限单独说明，不混同为宿主沙盒 |
| 外部运行时中断后重启 | 重新关联已有任务；模型生成仍遵守未知提交处理 |
| 替换运行时 | 相同领域任务与素材版本继续可读，不迁移为某工具私有项目格式 |

## 本阶段不做

为了支持外部 Agent 而引入任意系统控制、多用户权限平台或无限自主循环。也不追求完整专业非线性剪辑软件、自动修复一切质量问题或所有模型能力的统一最低公分母。

## 退出门槛

所选择的增强在至少一个真实作品流程中减少了操作或改善了结果，新增能力有清晰边界且没有破坏 P3 的恢复与成本语义。未被验证有用的增强可继续搁置。是否进入 P5，取决于是否确实需要更方便的启动与后台管理。
