# P2 · 分镜工作台与有界推理

> 状态：代码已实现；本地契约验证通过，真实模型验证待用户连接。见[验证记录](../validation/p2.md)。覆盖 FR-06–FR-08、FR-09 的合同骨架；外部推理涉及费用时同步覆盖 FR-11/FR-12 的基础保护。

## 目标

让用户围绕镜头持续创作，而不是反复在聊天记录和文件夹中寻找结果。先完成可靠的手工分镜、引用和版本，再加入可替换的推理模型，提供可审阅的结构化草稿。

## 前置条件

- P1 已能稳定导入、保存、预览和导出。
- 项目、素材和时间线均使用稳定 ID，已有迁移与备份机制。
- 已定义简报、风格说明、镜头修订、候选/所选素材和计划 schema。

## 范围与建议模块

| 模块 | 交付行为 |
| --- | --- |
| `apps/web` 分镜页 | 镜头列表、画面/参考/候选、右侧设置与底部时间线 |
| `packages/domain` | 简报/分镜修订、候选选择、局部依赖和差异应用 |
| `packages/providers` | 推理连接接口、能力清单、纯验证与计划编译骨架 |
| `packages/runtimes` | 有界原生任务循环，只使用明确允许的工具与修改合同 |
| `packages/storage` | 草稿、修订、输入快照、计划与调用记录 |

生成适配合同先使用模拟供应商验证，不宣称已经接通真实图片/视频。推理模型返回的计划也不能作为未经验证的供应商请求直接提交。

## 实施顺序

1. **手动先行。** 支持新建/修改/排序镜头，填写叙事目的、画面、动作、时长、字幕与素材方式；把已有媒体关联到镜头。
2. **候选与选择。** 导入素材也使用不可变版本；每镜明确保存所选版本，切换候选不删除历史；时间线引用明确的素材版本。
3. **草稿与差异。** 实现简报→分镜草稿的结构 schema；应用前展示新增/修改/删除差异，允许部分接受。并发编辑采用修订检查，防止旧草稿覆盖新修改。
4. **能力合同。** 定义文本、首帧、首尾帧、参考素材等计划方式与能力校验结果；模拟能力冲突返回可解释的 `needs_replan`。
5. **有界推理。** 接入一个实际可用的推理连接，或先保留纯手动模式。原生循环有请求次数、工具范围、超时和上下文边界；默认一次请求，无效结构不自动无限修复。
6. **调用边界。** 调用前冻结输入版本与连接，保留输出和超时上限；响应结果不明时不自动重发。界面可不填写本地费用预留，实际费用仍保持未知并以服务账单为准；原显式预留调用及历史结算继续兼容。
7. **一致性。** 修改字幕只更新合成依赖；修改视觉要求标记相关审核待更新；更改默认模型只影响未来计划。P3 在同一规则上接入真实生成。

MVP 的助理可以提出镜头和修改方案，不能直接获得任意文件、终端和删除权限。这里的原生循环也不意味着必须实现复杂多 Agent 系统。

## 验收情景与失败测试

| 情景 | 通过条件 |
| --- | --- |
| 完全不配置模型 | 用户仍可写出 4 个镜头、关联素材并导出 |
| 生成分镜草稿后只接受其中两镜 | 项目只产生用户接受的变更，其他镜头保留 |
| 模型输出不符合 schema | 草稿标记错误，既有分镜无变化；没有无限重试 |
| 请求过程中用户修改了同一镜头 | 返回草稿需要重新合并或审阅，不能静默覆盖新修订 |
| 切换当前选用候选 | 历史素材、所选标记和导出引用一致 |
| 首尾帧意图选择仅首帧能力 | 编译被拦截；接受单首帧方案后生成独立新计划 |
| 远端推理响应丢失 | 显示调用状态不明，不因刷新/重启自动发起第二次计费请求 |
| 接口拒绝推理请求 | 保留 HTTP 状态与白名单错误分类，显示额度、权限或参数的处理提示；不暴露原始错误正文，不自动重发或确认零费用 |
| 模型输出包含任意命令或越界工具要求 | 不执行，不扩大任务权限 |

模拟供应商应覆盖能力校验和结构错误；真正的推理连接只需小规模验证输出合同与实际权限/成本边界。

## 本阶段不做

真实视频任务的长期轮询、完整视频费用结算、自动选择作品、全片语义审核、CC/Codex 集成和复杂精剪。推理调用可选；不可用时保留手工工作台，不阻塞用户已有素材的创作。

## 退出门槛

手工和模型草稿都通过同一分镜/版本合同进入项目，计划验证可解释，旧草稿和旧候选不会覆盖新要求。调用模型时的范围与费用边界可见。此时才将真实图片/视频请求接到 P3。

## 2026-11-08 补充：镜头列表与草稿高度限制

镜头列表和草稿审阅区按视口限制最大高度，长列表在各自区域内滚动；添加镜头、草稿选择和应用勾选项入口保留在列表外。展开长字段不会继续撑高草稿面板，手机保留横向镜头卡片。仅调整界面布局与滚动可访问性，原有逐项应用及过期草稿阻止规则不变。

## 2026-11-08 补充：统一推理连接与简化提交

分镜的推理连接同时支持模型 API 与已启用的 Codex CLI / Claude Code，显示实际配置模型与推理强度；分别复用原推理 Runner 与 CLI 草稿 Runner。移除本地预留表单及确认勾选，点击生成即可创建待审阅草稿。新请求无需预留金额，旧预留保留。输入版本、去重与未知结果不自动重发均继续验证；后台相同版本状态刷新不再重置请求标识，丢失本地登记回复时可用原标识查询。
