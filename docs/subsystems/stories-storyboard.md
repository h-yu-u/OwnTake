# 故事与分镜

## 当前责任

故事库是全局文本创作资产；作品是一次具体制作。故事、故事版本、剧本版本和作品来源关联由 [story repository](../../packages/storage/src/story-repository.ts) 持久化。故事修改保留历史版本，不悄悄修改已经创建的项目简报。

分镜工作台由 [StoryboardStore](../../packages/storage/src/storyboard.ts) 管理镜头、修订、候选和草稿。页面可编辑内容、明确采用候选、再将确定素材安排到时间线。没有模型连接时手工编辑与素材导入仍可使用。

## 版本与审阅

视觉、字幕和剪辑变化分开跟踪。修改画面要求后，旧候选仍保留但不能冒充符合新视觉修订；用户明确采用旧候选时保留版本提示。生成成功不自动切换当前选用素材。

模型/CLI 结果先成为有界草稿操作，仅允许新增、更新或归档等已定义行为，不接受任意命令。应用草稿时校验所属项目、基础版本和用户选择的操作集合，避免覆盖后来编辑。

故事来源与授权状态独立保存。搜索到链接、粘贴文本、AI 重写都不等于取得改编权。当前实现不承诺自动采集知乎/小红书全文，也不包含独立人物资产库；后续增加这些功能时必须先补真实能力与来源合同。

## 相关责任

生成与费用由[模型子系统](providers-generation.md)负责；时间线与成片由[媒体](media-studio.md)负责，界面未保存状态由[前端](frontend.md)负责。

## 验证

覆盖故事/剧本历史版本、冲突、来源关联、跨项目引用、草稿逐项接受、旧候选保留以及分镜到时间线的确定输入。参见 [story tests](../../tests/story-library.test.ts)、[storyboard tests](../../tests/storyboard.test.ts)。
