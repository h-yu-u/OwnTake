# OwnTake 交互原型

这一版原型用于讨论 **本地个人影像工作台** 的信息结构、界面与关键状态，不是正式应用。以四镜头、24 秒的个人短片「把闪念拍成片」为示例，串起项目简报、分镜、素材版本、能力适配、任务恢复和导出检查。

正式版的范围、架构与阶段安排分别见 [产品设计](../product-design.md)、[技术架构](../architecture.md) 和 [实施计划](../implementation-plan.md)。

## 打开原型

下载或克隆仓库后，直接用浏览器打开 [index.html](index.html) 即可。HTML、CSS、JavaScript 和概念画面全部在本目录中，不需要构建，也不依赖 CDN、字体服务或外部图片。

建议从仓库根目录运行一个仅监听本机的静态服务器，以便在固定来源下保留演示状态：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory docs/prototype
```

然后打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。GitHub 文件页展示的是源代码，需要在本地打开才能操作。

直接使用 `file://` 打开时，浏览器对 localStorage 的处理可能不同；若不能保存，原型会提示，并继续提供本次页面内的交互。更换端口或浏览器会产生独立的演示数据。

## 六个界面

| 界面 | 可以体验的交互 | 设计意图 |
| --- | --- | --- |
| 项目 | 查看项目、新建简报、切换项目、选择横屏或竖屏及画风 | 创作围绕项目组织，保留简报作为后续约束 |
| 分镜 | 切换镜头、预览静态节奏、比较候选、选用版本、修改字幕或画面意图、确认方案、模拟生成 | 用镜头与素材版本承载工作流；修改影响能被看见 |
| 素材 | 筛选全部、已选用、生成候选和导入 / 合成素材；新增导入示例；返回对应镜头 | 素材不会随新生成被覆盖，来源与选用关系分开 |
| 任务 | 查看状态与记录、核对未知提交、取消已知任务、定位生成结果 | 上游完成、素材入库、人工选用是不同状态 |
| 导出 | 检查缺失素材、旧方案引用与人工确认；模拟渲染；下载方案 JSON | 合成一个确定的时间线与输出规格快照 |
| 设置 | 查看虚拟能力清单、模拟环境检查、调整演示并发与当前项目额度、重置原型 | 模型提供方、代理运行时、媒体工具分别配置 |

桌面宽度下，分镜界面采用左侧镜头列表、中间画面与候选、右侧方案和能力设置、底部时间线。窄屏下依次折叠布局。主要操作使用原生按钮、表单与对话框，详情页签支持方向键、Home 和 End；对话框支持 Escape 关闭。

## 建议的验收顺序

每条检查都可在「设置 → 重置全部演示数据」后从相同初始状态开始。重置只清除该原型的演示状态。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 默认导出门禁 | 直接进入导出页 | 镜头 01 尚未选用，模拟渲染不可用；「处理」可返回对应镜头 |
| 最短完成路径 | 在镜头 01 选择已人工确认的 v1「柔光版本」，点击「选用这版」，进入导出 | 四个镜头均通过本原型的选用检查，可以模拟渲染；不会生成 MP4 |
| 选用与人工确认分开 | 选用镜头 01 的 v2，进入导出，再返回「审核与证据」标记人工确认 | 选用不会自动等于确认；确认前导出被拦截，模型与动态检查仍显示未检查 |
| 能力不兼容 | 镜头 01 保持「首尾帧 → 视频」，将适配器改为 Demo B | 显示尾帧不支持，阻止提交，不能通过勾选确认绕过；不会静默丢弃尾帧 |
| 明确重新规划 | 换回 Demo A，或明确将方式改为「首帧 → 视频」，再确认方案 | 已有素材保持不变；新方案重新确认后才能提交 |
| 新候选生成 | 点击「模拟生成新候选」，观察任务页，等待约 6 秒 | 依次演示提交、执行、上游完成、入库；产生独立候选，不自动选用；额度记录随状态变化 |
| 重复点击与并发 | 在设置中把并发调为 2 或 3，提交当前镜头方案后再次尝试提交相同方案 | 同镜头、同画面版本、同生成方案的未结束任务阻止重复提交；`submission_unknown` 也属于未结束任务 |
| 刷新恢复 | 在模拟生成执行中刷新页面 | 从保存的阶段继续演示；不会重新创建生成意图，也不会永久停在生成中 |
| 未知提交核对 | 进入任务，点击初始旧方案任务的「核对任务」，填写演示任务 ID，点击「模拟查到结果」 | 沿用原生成意图和尝试，直接进入结果入库；不会创建第二个请求；旧方案结果只进入历史，不覆盖当前选用素材 |
| 字幕局部变化 | 完成一次模拟渲染后，修改一个镜头字幕并保存 | 只更新该镜头的字幕版本与时间线；候选、画面方案和生成任务数量不变，上次渲染标为过期 |
| 画面意图变化 | 保存镜头 01 的画面意图修改，或应用镜头助手的示例建议 | 仅该镜头画面方案更新，历史候选保留但不再满足新方案；不自动调用模型，不修改其他镜头 |
| 输出规格变化 | 完成 1080p 模拟渲染后改成 720p | 上一次渲染显示过期；新规格按项目保存，重新模拟渲染后记录新的规格 |
| 导入与本地合成 | 在素材页添加示例版本，或对镜头 04 模拟更新合成候选 | 只新增占位素材记录，不读取文件，不执行媒体工具；新候选需要选择和确认 |
| 方案下载 | 在导出页点击「下载方案 JSON」 | 下载真实的 JSON 文件；包含 `demoOnly: true`、时间线、占位素材引用和阻断项，不伪装成视频 |
| 新建项目 | 输入名称与简报，选择画幅，创建演示项目 | 保存输入并载入四镜头示例；不会声称已根据简报生成剧情；切换项目后状态各自保留 |

原型中的「预览节奏」按镜头时长切换静态概念图，没有视频解码或音频。演示生成的约 6 秒只用于让状态可观察，不代表任何真实模型速度。

## 演示数据与边界

**真实实现的部分**是页面导航、浏览器表单、纯逻辑校验、占位素材版本选择、localStorage 状态保存和 JSON 下载。可编辑文本进入 HTML 时经过转义，载入状态时进行有限结构校验。浏览器禁用存储、状态损坏或清理站点数据后，不能把原型当作可靠项目备份。

**模拟的部分**包括模型生成、审核标记、环境检查、媒体导入、任务核对、取消、成本和最终渲染。图像为内联 SVG 概念画面，所谓视频候选没有媒体文件。API Key 输入禁用；没有网络 API、真实厂商请求、真实文件扫描或 FFmpeg 调用。

Demo A / Demo B 是虚拟能力清单，分别演示首尾帧与仅首帧的能力差异。这里校验生成方式、画幅和时长；没有真实首尾帧文件、参考资产、厂商条件组合或完整请求 schema，不能据此判断某个真实模型是否兼容。

任务由浏览器定时器推进。刷新后会从 localStorage 恢复模拟阶段；关闭网页会停止定时器，重新打开后再继续。正式版则由独立的本地服务和 SQLite jobs 管理任务，网页不承担后台执行职责。这个原型不能用来证明真实任务的崩溃恢复、幂等提交、扣费安全或进程隔离已经实现。

`submission_unknown` 没有自动推进分支，也没有重发按钮。演示的核对只支持「找到原结果」一条路径；正式版还需要上游幂等查询、明确未受理、仍不确定、人工记录等恢复分支。取消演示保留已提交任务的示意成本，不表示任何厂商承诺退款。

新建项目使用同一套示例分镜；画面意图中的「镜头助手」提供固定建议。正式版的结构化剧情规划、图片生成、真实媒体导入、音频编辑、自由时间线、批量操作、CC / Codex 运行时适配和 Electron 封装均未在此实现。
