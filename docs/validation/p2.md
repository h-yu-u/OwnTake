# P2 实现与验证记录

## 本阶段结果

手工分镜、不可变候选、分层修订、草稿差异与部分接受已接入真实应用；不配置任何模型仍可完成分镜与已有素材的创作。推理连接是可选能力，返回待审阅草稿，不会自动修改镜头或触发图片/视频请求。

### 使用路径

1. 创建项目后在「分镜」添加镜头，填写画面、动作、时长、字幕与参考素材。
2. 在「工作台」导入已有媒体，回到分镜将素材加入候选，再明确选择一版。旧候选可以手动选择，但视觉版本差异持续显示。
3. 镜头都选好后「保存到时间线」，再进入工作台调整、导出。P2 只保存镜头字幕内容，字幕烧录于 P3 接通。
4. 「草稿与调用」支持手工提出修改草稿，查看字段差异，仅应用勾选项。旧草稿需重新审阅，不能覆盖新的分镜修订。
5. 在设置添加推理连接；模型名称必须按实际账号填写。连接需要支持 Chat Completions 的严格 JSON Schema、`max_completion_tokens` 等请求字段。不会在失败后自动降级参数或重发。
6. 推理前审阅简报/分镜版本、连接、币种、可接受预留与单次/项目上限。一次操作只有一次提交。响应未知保留预留；调用与草稿均能在刷新后查看。费用核对根据自己的供应商账单填写，不根据 token 数猜测实付。

## 实现边界

- `Shot.revision` 为编辑乐观锁；视觉、字幕和剪辑依赖分别递增。旧视觉候选保留来源，不会冒充新要求已完成。
- 模型调用冻结项目简报版本、分镜版本、模型连接、密钥引用版本和预留。改默认连接只影响未来调用。
- 密钥保存于应用数据目录的 0600 文件；公开响应、数据库 profile 和事件不含密钥。更换服务 origin 必须重新提供该服务密钥，不携带旧服务凭据。
- 原生运行时一次请求、无工具/终端/任意文件权限、有限上下文/输出/超时。只接收严格分镜操作 Schema。
- 服务退出时取消本机等待；已开始的远端请求可能仍处理，恢复为 `submission_unknown`，不会自动再提交。
- schema 升级到 2，原 P1 数据及 v1 备份可迁移；备份保留完整分镜和候选/草稿历史，凭据文件仍独立于备份。

## 验证

实际环境延续 P1 的 Linux / Node 24 / FFmpeg 环境。自动检查覆盖：

- 严格字段白名单、非法指令拒绝、局部修订和旧修订快照。
- 旧候选、显式选择、跨项目拒绝、归档与重排。
- 草稿部分接受、重复应用拒绝、旧草稿冲突及应用中途事务回滚。
- v1 数据和备份升级，完整分镜备份恢复。
- 一次 POST、结构错误/截断/工具调用拒绝、HTTP 失败脱敏、重定向拒绝、响应体读取超时和断流未知状态。
- API 冻结与去重、未知调用在重启后不补发、费用预留阻断、人工核对、公开 DTO 不泄露密钥、更换 origin 不复用旧密钥。

实际执行 `npm run check`：类型检查、41 项测试、生产构建全部通过。Chromium 153 实际操作 4 镜头创建、候选关联/采用、保存时间线、导出、刷新通过；数据库确认恰好 1 个成功导出，页面无 JavaScript 错误。测试环境补充 Noto Sans CJK 字体后也检查了分镜界面的中文布局。测试只访问本地 HTTP 契约服务，未使用真实模型凭据、未产生真实调用费用。连接能力状态始终保留 `unverified`；真实账号、输出质量和实际账单仍需目标环境核验。

## 官方协议依据

[OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 用于核对请求格式、严格 JSON Schema、输出 token 上限与禁用工具。一个兼容路径不自动保证模型支持这些参数；实际不支持时界面显示失败并保留手工流程。
