# P4 · 创作工具与本机运行时

## 交付范围

「创作工具」提供配音、有限抽帧审核和可选本机 CLI 分镜草稿；原来的手动分镜、原生推理、导入素材和导出流程继续可用。字幕样式、裁切入点、音量及淡入淡出已在 P3 接通，本阶段复用同一时间线。

| 工具 | 输入与产物 | 应用方式 |
| --- | --- | --- |
| 配音 | 审阅文字、voice、速度及可选指令，生成独立 WAV Artifact | 试听后到素材剪辑页明确加入音轨；不会替换旧旁白或自动调整字幕 |
| 抽样画面审核 | 选择一个候选，发送图片单帧或视频 10% / 50% / 90% 三帧，返回有证据 ID 的只读报告 | 结合证据帧和人工观看判断；不改变候选、选择、时间线或人工审核状态 |
| Claude Code / Codex | 冻结简报与分镜，调用用户明确启用的本机运行时，返回结构化修改草稿 | 在现有「草稿与调用」中逐项接受；不会自动修改作品或执行媒体生成 |

## 模型连接

配音采用 `openai-speech` 协议连接，声明 `capabilities.speech`：voices、最大文字长度、可用速度区间与是否支持 instructions。输出固定为 WAV，输入最多 4096 字符；超限不会自动拆成多次调用。声音和模型名称由用户填写，不用固定默认值冒充真实账号支持。

审核复用 `chat-completions`，需额外声明 `capabilities.frameReview.maxImages`；它表示该连接支持图像输入与严格 JSON Schema 输出。旧连接没有该声明时只能继续原有文本推理，不会自动发送图片。审核最多发送三张 640 像素边界的 PNG，证据图片、请求采样时间与摘要保存在 SQLite 中，随项目备份保留。`requestedTimeMs` 是请求采样位置，不是解码器测得的精确 presentation timestamp。

截至本次核对，OpenAI 的旧 Speech 模型在官方文档中已标明 2027-01-06 停服计划，因此本适配器定位为可配置的 **OpenAI-compatible Speech 协议**。Realtime 是另一套接口，不能只换一个模型名就认为兼容；如目标服务仅支持 Realtime，需要另加适配器。参见文末官方生命周期资料。

## 本机 CLI 设置

在设置中填写绝对可执行路径、运行时类型、实际模型与超时。配置默认关闭；启用时需要明确认可它是使用本机现有 CLI 登录和本机权限的可信扩展。界面检查只执行版本和帮助命令，报告可执行文件 / 必需参数兼容性，认证始终为 `not_checked`。

- Claude Code 使用非交互 JSON + JSON Schema，关闭内置工具并使用空的严格 MCP 配置，要求 safe mode、无会话持久化和最多 3 个 turn。Schema 所需的内部 StructuredOutput 工具允许返回结构化结果，MCP 工具显式拒绝；不使用会同时阻断内部格式工具的全局通配拒绝。
- Codex 使用非交互 JSONL + 输出 Schema，请求只读权限、关闭支持的 shell / hooks / apps 等能力、忽略用户配置并禁用相应请求重试。
- CLI 上下文通过 stdin 传入；没有任意 shell 模板、额外参数或模型可修改的 cwd / env。每次在专用工作子目录运行，仅暴露冻结快照。
- 子进程环境采用白名单，不传 OwnTake 模型 API Key、`NODE_OPTIONS` 或注入变量。原有 HOME 与相应 CLI 认证目录变量仅原样继承；OwnTake 不读取、复制或导出其中的凭据内容。
- 不把参数约束表述为独立的操作系统隔离。CLI 管理员策略、自带工具、系统 keychain 和安装版本仍属于可信本机扩展的边界。
- 一次启动不保证 CLI 内部恰好一次模型请求。应用请求关闭已知重试，并在启动后失败 / 超时 / 取消时保留未知费用；不会自动再次启动。
- stderr 持续消费并有内存上限，但原始内容不持久化、不回传界面。进程取消终止 OwnTake 管理的本地进程组，不代表供应商撤销了远端工作。

缺少 CLI、参数不兼容或未登录不会阻塞手工及原生推理流程。应用不自动安装或登录 CLI，也不会在版本不支持限制参数时删除这些参数来继续执行。

## 持久化与恢复

schema 4 新增运行时配置、创作任务台账、完整回复暂存和采样证据表。`studio_operations` 与 reasoning / generation 共用项目同币种费用核算，创建意图和预留在同一个 SQLite 事务中完成。`clientRequestId` 重复但输入改变会返回冲突。

同步外部回复完整到达后，先将有界字节及 SHA256 事务写入 `studio_receipts`，再发布素材 / 草稿 / 报告。音频上限 32 MiB；临时完整回复会进入一致性数据库备份，避免另漏一份未登记配音文件。收到回复但本地入库失败时，仅恢复已有回复；入库成功后删除暂存 BLOB，已经发布的音频由既有媒体备份规则保存。采样证据图则保留在数据库中供审核追溯。

服务启动时，有完整回执的任务继续本地处理；没有完整回执的已提交任务进入 `submission_unknown`。任务的当前币种预留保留，用户对照实际账单结算。提交前检查失败 / 尚未发送时取消才可记录为零费用。

审核始终绑定候选的原视觉版本与原 Artifact SHA。旧候选使用对应历史分镜的画面要求，迟到报告不会被解释为当前新版本已通过。覆盖固定为 `sampled_frames`，完整动作和音频为 `not_checked`；模型不能改写这一覆盖范围。

## 验证与外部条件

本阶段使用真实本机 HTTP、SQLite、FFmpeg 以及可审查的 CLI 夹具验证；没有发送真实付费提示词。`npm run check` 通过：服务端与前端类型检查、102 项自动测试、生产构建。最后核对内部格式工具边界后，CLI / runtime API 相关 11 项回归再次通过。浏览器走通配音、三张真实 PNG 证据帧的审核、CLI 待审阅草稿和刷新恢复；三项操作完成、两个供应商 HTTP POST、一个待审阅草稿，原镜头与选择未被自动修改，浏览器无 JavaScript 错误。

在独立临时目录安装官方包，只运行版本与帮助诊断：Codex CLI 0.167.0、Claude Code 2.1.319 均报告可执行且必需参数兼容，认证保持 `not_checked`。Claude 隐藏的 `--max-turns` 通过仅含 `--help` 的有效 / 无效数值探针确认，既没有传入生成 prompt，也没有读取登录文件。

实际登录后的 CLI 草稿调用、真实 TTS 语音质量、真实视觉模型准确性、供应商费用与目标 Mac keychain 仍待用户环境验收。测试报告中的“通过”表示合同、状态和本地媒体处理检查通过，不表示模型主观质量或完整视频审核通过。
