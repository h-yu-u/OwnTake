OwnTake 是一个在自己电脑上运行的 AI 短片工作台：从创意和脚本出发，以分镜为单位组织素材、模型生成、候选版本、审核和剪辑，最终导出视频。首个目标是单人、单机、macOS 自用。

## 架构结论

**先做本地 Web：Vue 3 + TypeScript + Vite 前端，Node.js + TypeScript 本地服务，SQLite 与本地项目文件，FFmpeg / ffprobe 处理媒体。**

浏览器提供界面，Node 服务负责文件、模型调用、CLI 子进程和后台任务。关闭网页不代表任务取消；停止本地服务或电脑休眠则按任务类型进入恢复流程。安装与依赖版本已在 package-lock.json 锁定；正式入口与静态原型保持分离。

“本地运行”描述应用和数据的部署位置。调用外部模型时，所选提示词及参考素材仍需发送到相应服务；也可接入满足能力要求的本地模型端点。无需账号体系、团队协作、商业计费、云数据库或分布式队列。

### 三个独立的适配边界

| 边界 | 职责 | 例子 |
| --- | --- | --- |
| `ModelProvider` | 推理、视觉检查、图片、视频、音频等模型能力 | 可调用的模型 API、本地推理端点 |
| `AgentRuntime` | 有界任务循环、上下文、工具权限和结构化结果 | 内置任务执行器；后续可接 Claude Code / Codex |
| `MediaTool` | 确定性媒体操作、探测和导出 | FFmpeg、ffprobe |

CC / Codex 的运行时职责与模型 API 分开设计。镜头提出能力需求，执行计划经校验后交给适配器；更换供应商时不会悄悄丢掉尾帧、参考图或音频条件。

## 运行当前原型

克隆仓库后，可以直接打开 `docs/prototype/index.html`。为了让浏览器本地存储行为保持一致，也可以在仓库根目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory docs/prototype
```

然后访问 <http://127.0.0.1:4173>。此命令只启动原型静态服务器，不会启动正式 OwnTake 后端，也不会调用模型或 FFmpeg。停止预览服务可在终端按 `Ctrl+C`。

建议体验顺序：

1. 进入分镜工作台，切换镜头与历史候选。
2. 将首尾帧镜头切到只支持首帧的演示模型，查看能力不兼容提示。
3. 恢复兼容模型，模拟生成，再手动选择新候选。
4. 修改字幕，观察只需更新字幕及最终导出。
5. 在任务页核对“提交结果未知”的旧任务，观察结果不覆盖当前选择。
6. 在导出页查看缺少选中素材的阻断项，补齐后模拟导出。

完整操作细节以 [原型说明](prototype/README.md) 为准。

## 必须保持的产品规则

- 镜头、生成意图、供应商尝试、产物版本、时间线版本分开记录。
- 新候选不会自动覆盖已选素材，旧方案迟到的结果不会冒充新方案完成。
- 供应商任务成功、文件落盘完成、审核完成是不同状态。
- 已提交但无法确定远端是否受理的任务进入 `submission_unknown`，先核对；不通过自动重发制造第二次付费生成。
- 字幕、音量、顺序与画面分别跟踪依赖；上游修改先标记受影响内容需要复核，不自动重做全片。
- 费用是用户自己的 API 使用估算、预留和实付记录，不构建商业计费系统。
- 预览图上的检查不能被表述为已检查完整视频运动或声音。
