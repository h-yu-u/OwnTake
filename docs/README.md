# 文档导航

文档按**责任与读者**拆分，不按一次开发过程堆叠。当前行为以源代码、对应子系统文档和本次验证记录为准。根目录 README 面向使用者，AGENTS 面向贡献者，LESSONS 保存可复用的工程教训。

| 问题 | 入口 | 维护责任 |
| --- | --- | --- |
| 产品能做什么、怎样启动 | [中文 README](../README.zh-CN.md) / [English](../README.md) | 用户入口，与真实能力同步 |
| 改代码先读什么 | [AGENTS](../AGENTS.md) / [代码规范](code-standards.md) | 贡献规则，不重复实现细节 |
| 进程与模块如何协作 | [架构总览](architecture.md) | 稳定边界与依赖方向 |
| 某个功能现在怎样工作 | [子系统目录](subsystems/README.md) | 每个领域唯一的当前行为说明 |
| 如何开发和测试 | [开发指南](development/README.md) | 工具链、命令与验收层级 |
| 数据如何备份与移动 | [配置和备份](operations/data-and-configuration.md) | 数据与凭据安全 |
| 如何打包和发布 | [发布操作](operations/release.md) | 目标、命名、签名、校验与人工步骤 |
| 为什么坚持某条工程规则 | [LESSONS](../LESSONS.md) | 规则、原因、代码/测试证据 |
| 旧阶段曾做什么 | [历史索引](history/README.md) | 明确 revision 的历史证据 |

## 文档维护规则

行为变更与所属子系统文档在同一个 PR 修改。字段、阈值、目标名称的权威定义留在代码，文档引用其位置，不维护第二份可执行配置。文档检查验证维护入口的相对链接与必要结构，不能证明业务行为；业务验收仍靠相应测试。

`phases/`、`validation/` 和 `prototype/` 保留设计与交付历史。历史测试通过只证明记录的提交和条件，不代表最新代码、真实付费供应商或所有操作系统。旧路线图不应被当成当前功能承诺。
