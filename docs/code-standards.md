# 代码与文档规范

## 围绕行为拆分

模块按完整责任拆分，名称说明用途。路由只处理协议；事务、资产发布和任务协调属于用例。纯校验/归约与网络、磁盘、时钟、随机数分离，必要时注入这些依赖。不要为了每个 CRUD 操作建立空壳 Service，也不要让一个页面成为所有业务的全局控制器。

单文件变长时按变化原因拆分，不按机械行数切割。新抽象至少对应真实共享行为或明确边界，禁止无实际调用的未来扩展骨架。

## 输入与版本

边界接受 unknown 后严格解析。保持错误码、枚举、字段限制和幂等行为一致；不得通过隐式类型转换接受本应拒绝的输入。HTTP Schema 校验形状，领域验证业务语义；客户端校验不能替代服务端。

更新持久对象使用期望版本检查；已提交的外部任务引用确定版本。同步 SQLite 事务中不执行 await、网络或媒体子进程。新 Schema 需覆盖从旧版本升级、失败回滚及备份恢复。

## 常量与配置

- 共享业务限制供前后端共用，放共享合同或纯策略模块。
- Host、请求限额、缓存、会话、SSE 和时间线默认值由 `apps/server/src/config/` 负责。
- 外部 Provider 的协议限制放其适配层；不能由提示词任意覆盖。
- 平台/架构/文件名由 `scripts/release/targets.mjs` 单一声明，CI 和文档工具消费它。
- 密钥不进入常量、fixture、项目 JSON、日志、错误回显或发布清单。

## 副作用所有权

资源创建者负责释放。关闭可重复，部分初始化失败也可清理。流式上传限制实际字节数，失败清理临时文件；先完成文件完整性验证，再事务发布可用资产。网络请求有超时和响应大小上限，付费提交不因超时自动重发。

## UI 与可测试性

使用现有 Naive UI 和共享组件，状态逻辑放 composable，纯格式化/规则放普通模块。保留错误、空状态、加载、未保存和冲突提示。测试使用可访问名称或稳定语义定位，并先滚动到可交互区域；不要用强制点击或删掉断言掩盖布局回归。

## 验证与交付

`npm run check` 包含文档和发布工具检查、三端类型检查、应用测试、生产构建与独立服务 bundle 冒烟。分平台打包检查与真实 Electron 窗口测试不能被类型检查代替；真实账号/计费/签名/安装器交互需单列验收。

每个 PR 写明范围、迁移、回退、测试命令与未验证项。证据必须对应最终提交。文档不记录瞬时进度，不复制测试日志充当说明；在所属子系统记录新行为，必要时在 LESSONS 写规则、原因和证据。
